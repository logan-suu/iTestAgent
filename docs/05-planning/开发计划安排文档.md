# iTestAgent 开发计划安排文档

## 0. 文档说明

本计划基于全部文档（用户故事与验收标准、架构设计、技术选型、数据流全链路、AI Native 开发手册、开发避坑手册）编制，给出**分阶段、可执行、可验收**的开发排期与任务拆解。

配套文档：

```
iTestAgent 全量用户故事与验收标准规格书
iTestAgent 架构设计文档
iTestAgent 技术选型文档
iTestAgent 数据流全链路技术说明文档
iTestAgent AI Native 开发理念与实战技巧手册
iTestAgent 开发避坑与关键注意点手册
```

排期单位约定：

人力：1 名独立开发者（全栈，AI Native 全程） 相对周 W 按单人全职折算，兼职按投入比例线性放大 里程碑以可验收结果为准，不以代码量为准

## 1. 总体策略

核心原则（来自避坑手册与可行性分析）：

```
1. 先 Spike 后功能：先验证真机链路与元素可定位性，再堆能力
2. 去风险 MVP：人在环路记录器 + 稳健性能趋势工具
3. 研究级能力后置：自动链路推断/自动断言/FPS 精确/xctrace 深解析 标 Deferred/实验性
4. 每阶段以 P0 验收为门槛，P1 允许已知限制并声明
5. AI Native 全流程：规格即上下文、小步可验证、真机必实测
```

阶段总览：

```
Phase 0  立项与多 Backend 横评（决定路线）
Phase 1  骨架与环境（CLI/TUI/contracts/Server/doctor/devices/store/config + Simulator spike）
Phase 2  项目分析与 TestPlan（Project Profile + 计划确认）
Phase 3  真机执行核心（构建安装 + XCUITest + DeviceBackend 探索录制）
Phase 4  证据/性能/报告（稳健性能子集 + 三件套报告 + 归因）
Phase 5  打磨与 MVP 验收（Flow 重放/重跑/安全/门禁）
Phase 6  真机全闭环收口（P0 恢复线）
Phase 7  MVP 后增强（可选）
```

## 2. Phase 0：立项与多 Backend 横评（约 W1-W2）

目标：用最小成本验证各层 backend 候选，选出 MVP 最优组合。

核心原则：**不预设单一工具路线。** 每一层都做 2-4 候选横评，用 Phase 0 spike 数据决定 MVP 主力 backend。

任务：

```
T0.1 建仓与工程规范
T0.2 Device backend 横评（最高优先）
T0.3 Performance backend 横评
T0.4 TUI backend 横评
T0.5 Project analyzer 横评
T0.6 技术验证结论
  - monorepo(Bun)、AGENTS.md、schemas/、fixtures/、mock backends 脚手架

  - Spike A: mobile-mcp 路线 — 设备发现、安装/启动 app、UI tree、截图、tap/swipe/type
  - Spike B: Appium/WDA 路线 — WDA 签名安装、Appium session、page source、screenshot、gesture
  - Spike C: iphone-use 路线 — iPhone Mirroring + WebRTC + 视觉 fallback（仅当 A/B 失败时）
  - Spike D: mock backend — fixtures 模拟所有 backend 输出，保障无真机开发和 CI

  - Spike P1: XcodeTraceMCP / @xctrace-analyzer/core — trace export、hitches/hangs、not_exportable
  - Spike P2: instrumentsmcp — 录制+分析+report 一体化（T0.3 发现数据诚信问题，降级为参考）
  - Spike P3: raw xcrun xctrace export — 最小自研 fallback

  - OpenTUI: 验证长日志、Markdown、工具调用卡片、Bun 打包
  - ~~Rezi~~: 已排除（npm rezi 是 2015 CSS 工具，非 TUI 框架）
  - Ink: 验证最小交互版是否足够支撑 MVP

  - XcodeQuery CLI: 验证 JSON 输出是否足够稳定（T0.5 结果：本机不可用，降级为 optional future）
  - XcodeProj + xcodebuild: 传统方案作为对照

  - 输出决策矩阵 + Phase 0 横评报告
  - 确定 MVP 各层 backend 选择
```

里程碑 M0：

```
- device backend 至少一路在真机上跑通（截图+UI tree+launch time）
- performance backend 至少一路能获取 hitches/hangs
- TUI backend 至少一路能跑通交互式 Shell
- 决策矩阵明确：每层选 MVP 主力 + fallback
出口标准：M0 未过则暂停功能开发，先解决真机/性能瓶颈
```

决策矩阵：

| 如果 | 则 |
|---|---|
| mobile-mcp 真机稳定且付费账号可用 | 可补测后作为 mobile-mcp device backend |
| mobile-mcp 被云壳/免费账号限制阻断 | AppiumBackend 做主线（T0.2b 验证免费账号可用） |
| WDA UI tree 质量差 | 研究 iphone-use 视觉 fallback |
| XcodeTraceMCP core 稳定 | 性能模块优先复用 core |
| XcodeTraceMCP core 不适合依赖 | raw-xcrun-minimal fallback |
| OpenTUI 不稳定 | Ink fallback（T0.4 已验证 16/16 通过） |
| XcodeQuery CLI JSON 稳定 | ~~优先作为 Project Profile backend~~ → T0.5 不可用，raw xcodebuild + Tuist/XcodeProj 优先 |

## 8. Phase 6：真机全闭环收口（P0 恢复线，约 W19-W26）

目标：修复“组件和 Spike 已存在、生产入口未贯通”的实现偏移，交付可从 TUI 一句话触发、经用户确认后在真实 iPhone 完成测试并产出可解释、可重跑结果的产品闭环。

本阶段是 Phase 5 MVP 出口的纠偏主线，任务编号为 T6.1-T6.12。原可选增强任务迁移至 Phase 7（T7.1-T7.7）；在 M6-PHY 通过前，不再以组件单测、固定成功 probe、独立 backend spike 或手工构造报告输入作为“全闭环完成”证据。

### 8.1 已锁定的实现偏移

```
- TUI AgentSession 仍注册 MockDeviceBackend，analyzeProject/getDeviceInfo 为提示或固定返回
- CLI explore 仅固定 launch + screenshot，未由已确认 TestPlan 驱动动态动作
- 真机 explore 只写 artifact-index.json 到临时目录，未接 RunStore/三件套报告
- run flow --execute 使用错误 workspace 包名，真实 Appium 与 mock fallback 均无法解析
- rerun 只读取原 run/plan 并打印，尚未重新调度执行
- ReportSynthesizer、FailureExplainer、FlowReplay、BuildDriver 等组件存在，但缺少同一生产 run 的组合入口
- 部分所谓 MVP 集成测试只验证函数/薄桩存在，不能证明真实数据贯穿
```

### 8.2 任务拆解

```
T6.1  闭环契约与失败基线：锁定生产调用图、AC 矩阵、禁止 mock/薄桩冒充 E2E 的红测
T6.2  TUI 生产会话组合：真实 ProjectAnalyzer（含 analysisTier/limitations）/设备发现/BackendSelector/PermissionEngine，移除固定结果
T6.3  一句话到已确认计划：workspace -> Project Profile -> Intent -> TestPlan -> TUI 修改/确认/取消
T6.4  真机执行前置链：App 来源归一化/验证 -> xcodebuild -> R7 -> devicectl install/launch -> Route B/C 主动 readiness 对比与自愈（独占 DEF-031）
T6.5  双路径生产调度：确认前解析可执行 XCUITest 配置并锁定路径；无可执行配置或显式选择时走 Appium DeviceBackend，执行后禁止语义 fallback
T6.6  探索执行与 Flow 记录：动态动作、逐 case UI tree checkpoint、断言确认、run steps、可重放 Flow
T6.7  Flow 真机重放：修复生产包解析和 backend 构造，禁止静默降级 mock，保留 targetKind/证据
T6.8  RunStore 与报告贯通：单一 run 写入 ~/.itestagent，生成 plan.yaml + 三件套 + artifacts
T6.9  解释与真实重跑：explain 消费本次 run 证据；rerun --failed-only 实际调度并关联 parentRunId
T6.10 可靠性与安全收口：OpenTUI 交互、session teardown、T6.4 readiness 门禁回归、R7/R6/abort/redaction（不重复实现 DEF-031）
T6.11 自动化跨包闭环测试：同一生产组合覆盖 TUI 指令到报告/解释/重跑，mock 仅作 CI 传输替身
T6.12 G5 真机出口验收：真实 iPhone 跑通两条执行路径并留档当前证据，人工确认后关闭阶段
```

### 8.4 里程碑 M6-PHY（真机全闭环）

```
- 用户在 iOS workspace 运行 itestagent，从 TUI 输入一句测试目标
- Agent 使用真实项目分析与设备状态生成 TestPlan；未确认绝不执行
- 自动确定/构建/安装/启动 App，并完成 WDA/Appium 可用性检查；失败给出可执行修复建议
- TestPlan 确认前按 ADR-029 解析可执行 XCUITest 配置；XCUITest 与 DeviceBackend 使用路径专属 readiness，执行开始后禁止静默跨路径 fallback
- 探索动作逐 case 采集 UI tree/截图并记录 run steps；Agent 建议断言必须经用户确认
- 同一 run 在 ~/.itestagent/runs/<run_id>/ 写入 plan.yaml、summary.md、result.json、artifact-index.json、artifacts/
- itestagent explain <run> 使用真实证据；itestagent rerun <run> --failed-only 真正执行并关联原 run
- 全链路无 MockDeviceBackend、固定成功 probe、错误包名或静默 dry-run fallback
- G1-G7 全过；真实 iPhone G5 新证据覆盖 exploration 路径与 XCUITest 路径（无测试资产时须提供专用 fixture app）
- T6.5 的 XCUITest 路径另需 CoreSimulator G5-SIM 证据；仅组件/fixture 测试不得宣称双目标闭环通过
- DEF-025/029/030/031/032/033 逐条验证：已修复则标 resolved，未修复不得宣称 M6-PHY 通过
出口标准：一句话 -> 计划确认 -> 真机执行 -> Flow/证据 -> 三件套报告 -> 解释 -> 真实重跑，全程使用生产组合并由当前 G5 证据证明
```

## 13. 单人独立开发者工作方式

单人 + AI Native 分工：人管决策，AI 管产出。人负责真机/Simulator spike 实测（G5 + G5-SIM）、签名与 backend setup 与设备处理、架构决策、AC 验收、危险操作确认、文档定稿；AI 负责读规格、出计划、写实现与测试、生成文档草稿。策略：串行推进；mock+fixtures 无真机也能写逻辑；真机/Simulator 任务集中验证；能复用绝不自研；研究级能力后置；每个 US 小步交付。
