# ADR-051：T6.12 按已验证能力收口与产品发布门禁保留

状态：Accepted。2026-09-17 用户明确选择“按已验证能力收口，正式追踪剩余缺口”。

## 背景

ADR-050 仅迁移 physical 零扫描/memgraph，不能自动覆盖其他性能缺口。US-12.1 原文 `AC1 覆盖 launch time / memory peak(近似) / crash / test duration / hitches/hangs` 保持产品要求。当前正常 TUI 双执行路径、真实 XCUITest failed-only 及已声明内存域已有 G5/G5-SIM；冷启动、其余逐指标实测、Simulator baseline/多轮、XCUITest 新增性能与有效归因仍有实现或验证缺口。源码依据见 t6.12-remaining-performance-review.md。

## 方案与决策

比较保持所有新增能力作为 T6.12 前置，与拆分验收任务和产品发布门禁。用户接受后者以结束持续扩大的验收任务。

1. T6.12 验收正常 TUI 双路径、canonical 报告、真实 failed-only/血缘、explain 安全读取及不确定性表达，以及已验证的 physical 内存增长/阳性/baseline/多轮/取消和 Simulator 单次内存/有效零扫描。最终仍需适用质量门禁和代码交付，不能立即标 done。
2. T7.9 / DEF-038 承担 US-12.1 冷启动来源、crash/hitches/hangs 的生产接线与逐项 G5/G5-SIM（适用域），复核 test duration 语义及内存近似标记。真实不支持必须显式声明，不能将 parser fixture 当已支持。
3. T7.10 / DEF-039 承担 US-12.2 Simulator baseline 首次建立、比较及 TUI 接受替换；保持目标域、采集来源隔离及失败不建基线。
4. T7.11 / DEF-040 承担 US-12.3 Simulator 可复现多轮与 XCUITest 新增内存采集；先确定生命周期/目标身份/契约，再实现与分域实测，不复用不相干性能证据。
5. T7.12 / DEF-041 承担 US-14.1 有效归因补强：真实可解释失败、证据安全投影与规则/受限模型调用，验证类型/置信度/建议及读者边界；证据不足仍 inconclusive，禁止泄露原始设备内容。
6. 上述任务均依赖 T6.13；T7.7 依赖新增任务。T7.8/DEF-037 范围不变。这些项虽然排在 Phase 7，但属于明确未完成的产品 AC，不因该阶段历史“可选增强”名称变为可选。
7. T6.13 可以继续签名向导与阶段集成验收。T6.12/T6.13 或 M6-PHY 的完成不等于全量 MVP 产品发布：相关性能与归因产品级门禁必须明确保留未通过状态，直到对应任务及证据完成。禁止借任务拆分宣称全部 P0/产品 AC 通过。

## 后果与验证

同步规格交付范围、计划、任务依赖、延期项及出口矩阵，保留历史失败和原始 AC。当前采集代码、权限、schema、报告和不支持行为不变。没有授权新设备操作、提交推送或合并。代码类交付仍须 PR 流程；T6.12 最终确认遵循原任务状态机。

延期原因是跨域采集设计、较大的实现/实测范围及用户明确接受的任务拆分，非以文档掩盖已能立即修复的小缺陷。门禁失败仍应在当前工作处理。
