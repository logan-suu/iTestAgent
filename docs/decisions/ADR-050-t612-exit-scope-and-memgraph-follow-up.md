# ADR-050：T6.12 出口收敛与真机零扫描后续任务

状态：已接受。2026-09-17 用户在范围审查后明确回复“好的按照你的建议进行”。

## 背景与原约束

T6.12 原始目标为生产入口的真机双路径闭环验收，后追加 US-12.3 内存能力。DeviceBackend 真机内存增长、阳性泄漏、baseline、多轮及取消已有生产证据，Simulator 单次阳性和有效零扫描也已有生产证据。physical 零扫描只有工具层 memgraph 对照，没有独立产品运行时的生产 G5。0.1.14 元数据探针仍无法验证目标；即使修复，完整 provider、身份、capture/export、TUI 接线及取消验收也尚缺。

ADR-044 原文：`延续 xctrace detected-only | 验证期间保留既有语义，不能关闭零扫描 AC`。原完整出口计划把 metadata 研究置于全部验收之前，导致可独立完成的双路径验收持续等待。本决策改变交付范围和任务归属，不把研究失败改成通过。

## 方案比较

- 保持全部范围：仍须完成真机零扫描完整生产自动化；当前可行性尚未证实，无法保证快速收尾。
- 把空表判零、用 CUA/手工导出当产品：拒绝，破坏证据与全自动要求。
- 正式拆分范围：保留已交付内存能力和严格不可用语义，原始双路径闭环优先；真机零扫描及独立 memgraph 运行时交由后续任务。用户选择此方案。

## 决策

1. T6.12 不再承担 physical 有效零扫描的生产实现与 memgraph 自动化研究；新增 T7.8，依赖 T6.13。T7.7 增加 T7.8 依赖，以保留 Phase 7 最终集成出口。仅登记，不启动 Phase 7。
2. US-12.3 AC4/AC5/AC6/AC7 的证据真实性、自动采集、生产入口、取消与双目标规则不放宽。physical 当前声明 detected-only；无可验证扫描结果仍 unavailable/not_exportable，不能输出 not_detected/零值或全项成功。physical not_detected 的生产交付与验收归 T7.8，US-12.3 不宣称所有目标/来源全量完成。
3. T7.8 承接 ADR-044–049 的候选代码、诊断、真实失败和已通过的局部证据；完整验收必须包括独立产品运行时、设备/构建/进程身份、owner 关闭、生产阳性/完成零扫描/取消及 canonical 报告。现有 CUA 工具对照、无目标/元数据探针不得替代这些证据。保留已接受的安全边界，不要求继续某一种尚未证实的查询技术。
4. 暂停新的 metadata/helper 安装、授权刷新和 probe 实测。既有源码、安装、备份及证据不删除，不自动启用未完成 provider。恢复 T7.8 时先重核范围/候选/授权，旧单次额度不复用。
5. T6.12 继续补齐当前正常 TUI XCUITest → canonical 报告 → explain → 权威 failed-only 子运行的真实证据，复用既有 DeviceBackend/性能成功记录。其他性能指标、Simulator 多轮/baseline、XCUITest 性能等剩余项不由本 ADR 自动延期或宣称通过；须在出口矩阵逐项审查规格、已声明支持与 limitation。
6. T6.12 保持 in_progress，T6.13 保持 pending。完成仍需 G1–G7、适用 G5/G5-SIM、交付代码审查及用户最终验收。T6.13/M6-PHY 不再因明确延期到 T7.8 的物理零扫描阻塞；其他出口条件保持。

## 后果与验收

增加 DEF-037（open，target_phase=7，T7.8），明确未完成能力与恢复入口。该延期来自技术可行性/跨阶段产品范围调整，已由用户批准，不将它记录为 resolved。只修改文档和任务追踪，不修改采集/报告语义、schema 或运行默认值。

T6.12 的逐项证据与剩余工作以 `docs/06-verification/t6.12-exit-matrix.md` 为当前入口；历史报告保留原结论与时间。本决策仅覆盖本节明确的 physical 零扫描/memgraph 范围，不授权新的设备、安装、签名、baseline、commit/push 或 merge 动作。
