# Migration Batch Records

This directory holds the machine-auditable execution records for the
iTestAgent promotion migration (branch `feat/mvp-e2e-promotion`, baseline
`73c99fbcc237cafc13279a322616ee0b5b97ff62`).

## Layout

```
docs/06-verification/migration/
  README.md                      this file
  manifest.schema.json           batch manifest JSON schema (G6)
  allowlists/                    per-batch literal file allowlists
    Bxx-files.txt                exact paths a batch may modify
  Bxx.json                       per-batch migration manifest (G6)
```

## Batch lifecycle

Each batch follows the promotion guide §12 protocol:

```
PRECHECK → RED → GREEN → GATES → MANIFEST → COMMIT → TAG → WAVE INTEGRATION
```

- `Bxx-files.txt` is the exclusive set of paths a batch may touch. Any path
  not listed requires a guide/allowlist revision first (hard stop).
- `Bxx.json` is the self-describing batch manifest validated by
  `scripts/validate-migration-manifest.ts` (G6). It does NOT record the batch
  commit SHA (no self-reference); it records `baseCommit`, `stagedTreeHash`,
  `baselineMode`, `baselineDigest`, gate commands/exits, payload file SHA-256
  and the rollback tag.
- Receipts (`*-baseline.json`, `*-gates.json`) live in the Git-dir-local
  `itestagent-receipts/` directory (never committed) and are deleted after
  the batch commit passes G6.

## Rollback tags

Every batch produces an annotated rollback tag `promo/bXX-*` per
`scripts/expected-batch-tag.ts`. Rollback follows the promotion guide §17
protocol (quarantine refs, never force-push).

## Evidence

Generated evidence lives in `docs/06-verification/evidence/` (tracked,
SHA-256 manifests) and is regenerated by batch B38. Old G5/G5-SIM reports are
historical; only B41/B42 reports are current.

See `docs/05-planning/promotion-plan-approval.json` for the approved execution
scope and `docs/decisions/ADR-024-promotion-approval-simplification.md` for
the single-developer approval simplification.
