## 已完成的当前闭环

正常 TUI XCUITest 父运行、真实 failed-only 子运行、canonical 血缘和清理已经通过，见 g5-xcuitest-lineage-6.12.md。CLI explain 的只读消费和不确定性表达通过，实际归因为 inconclusive/low，不计有效根因分类成功。既有 DeviceBackend/内存 G5 与 Simulator 单次 G5-SIM 保留，未重跑。

## 仍不能宣称完成的内容

规格原文：`AC1 覆盖 launch time / memory peak(近似) / crash / test duration / hitches/hangs`。

| 内容 | 当前生产代码依据 | 验收结论 |
| --- | --- | --- |
| launch time | performance-xctrace-analyzer/src/production-capture.ts 使用 --attach；逐指标明确排除 launch_time，reason=xctrace.attach_after_launch | 冷启动来源/生命周期未实现，不能靠重跑相同采集补齐 |
| memory peak/growth/leaks | physical xctrace 与 Simulator native 单次已有实测；physical 空 Leaks 保持无法检测 | 只保留已验证来源；physical 零扫描归已批准 T7.8 |
| crash、hitches/hangs | metrics-parser.ts 有 XML 解析；生产仅导出已知 schema，有值才能 collected；无值 not_exportable | 解析代码不等于本机真实覆盖，当前未建立逐项生产 G5 证据；不把空结果当无 crash/hang |
| test duration | confirmed-run-bundle.ts 从实际 startedAt/endedAt 计算，仅请求时写入 metrics；本次父子 execution.durationMs 已保存 | 实际执行时间存在；不冒充冷启动耗时或本批请求过性能指标 |
| Simulator baseline | production-memory-baseline.ts 排除非 physical/native 来源；planning-session.ts 要求 baseline=skip | 明确未支持，通用 BaselineManager 分域代码不能替代生产入口支持 |
| Simulator 多轮 | contracts/test-plan.ts 限定 memoryRounds 为 physical DeviceBackend；memory-rounds.ts 要求已确认 physical Flow | 明确未支持，需要契约/生产实现及 G5-SIM |
| XCUITest 新增内存采集 | production-run-executor.ts capture 创建在 DeviceBackend 执行回调内；未采集指标由 confirmed-run-bundle.ts 标 route_did_not_collect | 本次 metrics=[] 不覆盖新增性能；需要目标进程生命周期绑定与实测 |
| explain 根因分类 | 本次正常 CLI 返回 inconclusive/low，无规则匹配或模型 fallback | 没有编造，满足不确定性边界；无法计为有效归因场景覆盖 |

以上代码路径均相对 packages/，模块名省略 itestagent 前缀时以仓库实际目录为准。审查未启动设备、采集或安装，也未修改生产行为。

## 需决定的两种范围

1. **按已验证能力收口 T6.12（建议用于尽快结束本验收任务）**：另立 ADR，明确将冷启动、剩余 crash/hitches/hangs 生产来源与 G5、Simulator baseline/多轮、XCUITest 新增性能、有效 explain 分类补强转入有依赖和验收标准的后续任务。保留 T7.8 原范围。T6.12 仅验收双执行路径、真实 failed-only、已验证内存及安全失败语义；产品级 US-12.1/相关 MVP 性能门禁仍未全过，不能宣称全量 MVP 完成。新 ADR 必须明确 T6.13 可做集成检查但不能替代剩余产品级发布门禁。用户确认后才修改规格、任务、延期项，并继续最终代码/门禁交付。
2. **保留全部性能出口要求**：T6.12 保持 in_progress，先准备冷启动来源、进程绑定、Simulator baseline/多轮等分项设计与确认，再实施和分别 G5/G5-SIM。不能用相同 fixture 的重复跑测替代缺失实现，也不能承诺一次实测完成。

选项1已由用户接受；范围决策见ADR-051。具体完成仍需质量门禁与交付确认。
